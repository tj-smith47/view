### 1.2 Types and signatures

**view-core `msg.rs`**

```rust
/// Why the engine's channel closed, as the engine announced it.
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum EngineLeave {
    /// The channel closed with no announcement: a crash, a kill, or a typed `:detach`.
    Unannounced,
    /// `VimLeavePre` announced a quit.
    Quit,
    /// view asked the engine to detach (`:View session detach`).
    Detached,
    /// The engine sent `restart`; the new server listens at `listen`.
    Restarting { listen: String },
    /// The engine sent `connect` (`:connect {addr}`).
    Connecting { addr: String },
}
```

Precedence when several are recorded before EOF: `Restarting` / `Connecting` > `Detached` > `Quit` > `Unannounced`. `view_leaving` from `VimLeavePre` fires during `:restart`'s `:qall`, so the event must win.

**view-engine `process/attach.rs` (new)**

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum EngineAddr {
    /// A Unix socket on this host.
    Socket(std::path::PathBuf),
    /// A socket on a remote host, reached through an `ssh -L` forward.
    Forwarded { remote: RemoteSpec, far: String },
}

#[derive(Debug, Clone)]
pub struct AttachTarget { pub addr: EngineAddr, pub detachable: bool }

impl Engine {
    /// Connects to a running server and performs the same handshake a spawn does.
    pub fn attach(target: &AttachTarget, cfg: &EngineConfig) -> Result<Self, EngineError>;
    /// Moves this engine's ownership onto `target`, keeping an owned child alive.
    pub fn reattach(self, target: &AttachTarget, cfg: &EngineConfig) -> Result<Self, EngineError>;
    pub fn leave_report(&mut self) -> (ExitInfo, EngineLeave);          // beside stop_report
    pub fn leave_report_if_exited(&mut self) -> Option<(ExitInfo, EngineLeave)>;
    pub fn addr(&self) -> Option<&EngineAddr>;
}

// private: replaces `child: Child` in `Engine` (process.rs:995)
struct Link {
    child: Option<std::process::Child>,   // a spawned engine view owns
    forward: Option<std::process::Child>, // the ssh -L forward, tied
    keep_alive: bool,                     // detachable: Drop closes only the channel
    adopted: bool,                        // a server view did not spawn (restart, connect)
    pid: u32,
}
```

`Engine::drop` (process.rs:1611) by `Link` state:

| Link | Drop does |
|---|---|
| owned child, not `keep_alive` | `graceful_kill` as today (`qa!`, then kill) |
| `keep_alive` | closes the channel; the server keeps running |
| `adopted`, not `keep_alive` | `qa!` over RPC with a bounded wait; the orphan fuse (§1.3) covers a wedged server |
| `forward` present | kills the forward after the channel closes |

The connect uses `std::os::unix::net::UnixStream`, `try_clone` for the reader half, and `EngineHandle::start_pumped(reader, writer, pump, None)` (handle.rs:511), which is already generic over `Read`/`Write`. A bounded retry (50 ms steps, total under the startup budget) covers the `--listen` handoff race.

### 1.3 Lifecycle

```
                       view                 view --detachable / --session NAME
                         |                              |
                  spawn --embed (tied)       spawn_detached nvim --headless --listen <sessions>/<name>.sock
                         |                              |
                         v                              v
                  +------------+   :View session detach   +-------------+
                  |  ATTACHED  |------------------------->|  DETACHED   |  server + buffers alive,
                  |            |  terminal closed / ssh    |  (no UI)    |  listed by `view --list`
                  |            |  dropped (detachable)     |             |
                  +------------+-------------------------->+-------------+
                    |  |  |  ^                                |      |
       typed :detach|  |  |  | view --connect NAME           |      | view --kill NAME [--force]
     (any session)  |  |  |  +--------------------------------+      v
                    |  |  |       REATTACHED = ATTACHED            GONE (socket, pid file removed)
                    |  |  |
                    |  |  +-- :restart -> ["restart", addr] -> wait for EOF -> attach addr (orphan fuse armed)
                    |  +----- :connect {addr} -> ["connect", addr] -> attach addr; old server per F1 row
                    +-------- EOF, no event, child alive, servername accepts -> reattach in place
                              (default session: notice "not detachable; use view --detachable")

  EOF, no event, servername refuses  -> death -> existing restart/backoff (detachable: same name)
  :qa / :wq                          -> Quit  -> view exits; detachable server exits with it
  server gone while DETACHED         -> `view --list` drops it (stale socket unlinked on next allocate/list)
```

Orphan fuse: a server view adopted (the restarted server, a `:connect` target view did not start) gets `ORPHAN_FUSE_CHUNK`. On `UILeave` of view's channel, if no `UIEnter` arrives within 2 s and the session is not detachable, the server stops itself with `vim.uv.kill(vim.uv.os_getpid(), 'sigkill')`. Swap files stay on disk, which is how recovery finds the unsaved text. This keeps the S2 invariant "no stray nvim after view exits unless the person asked for a detached session" for servers view did not spawn and cannot tie.

### 1.4 Data flow of a reattach

```
reader thread                 loop thread                         attach thread
-------------                 -----------                         -------------
EOF; slot.leave()=X ----> EngineStopped
                              leave_report_if_exited()
                              note_engine_leave(exit, X)
                              Reattach(addr) -> spawn ------------> Engine::reattach / attach
                              keep painting last frame             UnixStream connect (retry)
                              (input queued, as at startup)        nvim_get_api_info handshake
                                                                   REATTACH_CHUNK + bridge chunks
                                                                   send Msg::EngineReady
                              EngineReady -> take engine
                              recovery::reattach_engine:
                                forget_engine_state()
                                finish_replacement()
                              scheduled view_vim_enter rpcrequest
                              -> existing VimEnter path: ui_attach, takeover, mappings
```

Pickers and panels start closed after a reattach. Unsaved text needs nothing: nvim holds it.

|---|---|

### 1.6 Platforms, security and interplay

- **Socket:** `<runtime>/view/sessions/<name>.sock`, dir 0700, created by view, socket created by nvim inside it. No TCP listener in any configuration. A `--connect` value containing `:` that is not `HOST:NAME` with a known ssh host form is refused before it reaches nvim, since nvim would read it as TCP.
- **Windows:** `--detachable`, `--session`, `--connect`, `--list`, `--kill` and `detachable = true` refuse with `Detachable sessions arrive with Windows support.` Typed `:detach` on Windows takes the restart path (swap recovery) with a notice. `:restart` on Windows: view stops the old server with one bounded `nvim --server ADDR --remote-expr "execute('qa!')"` (a new spawn row) and takes the normal restart path, because nvim documents its own Windows restart limitation. The named-pipe client lands with the Windows tier-1 work because it needs overlapped I/O and this tree allows no `unsafe` outside the existing FFI files.
- **Speculative echo:** a pending prediction is dropped with the overlays (`forget_overlays`) at reattach. No other change.
- **Supervision:** heartbeat and prober are fresh per attach (`start_pump`, `spawn_prober`). A detachable session that dies is respawned under the same name. Detach is a third deliberate state, never counted toward the restart budget.
- **Remote transport:** a remote detachable session is reached through an `ssh -L` forward (F3). A dropped ssh re-forwards and reattaches on the existing backoff and never respawns the far server. A remote default session keeps today's stdio-over-ssh path.

## 2. Performance bound (owed in commit bodies)

- **Reader thread:** one first-string compare per `redraw` batch (`scan_lifecycle`), plus a mutex store on the two lifecycle events and on `view_vim_enter`. No I/O under the lock. Stated in T3.
- **Key dispatch, grid apply, paint:** unchanged in a default session. A detachable session's transport is a Unix socket instead of a pipe; T10 measures key → RPC on it as a diagnostic.
- **Reattach:** runs on a background thread; the loop paints throughout. The handshake is `nvim_get_api_info` plus two chunk executions plus the existing VimEnter path. T11 seats `reattach.settled_ratio_p50` as a felt row in the startup budget class.

## 5. Left out of the charter, and why

| Item | Why |
|---|---|
| `connect` / `restart` in the oracle's `KNOWN_UNMODELED_EVENTS` (recon) | The tree shows it would break `known_unmodeled_events_match_a_live_session`; T3 scans raw batches instead. |
| A default key for detach | The charter names none. `:View session detach` and nvim's `:detach` cover it. |
| `:View session connect` | nvim's `:connect` is the in-editor form and T5 implements its event. |
| A TCP listener | The charter's security note and this plan's socket rule: no TCP by default, and no option for it. |

Every charter requirement is in a task: deliberate detach (T6), unexpected-disconnect survival (T6, T12 leg 5), `view --connect` with an address syntax (T7, F2), the connect and restart events (T5), detach as a third state (T3, T6), `:connect!` UX (T5), the `--listen` handoff race (T1, T4), and the four exit gates (T9, T11, T5's paint test, T12's supervision leg 7).

## 6. Known limits (stated in T6's commit and the spec decision entry)

- A default session that is detached with nvim's `:detach` stays attached with a notice; only sessions started detachable survive.
- `:connect!` stops the old server as nvim defines it; view cannot stop it from happening and reports what was unsaved.
- Windows refuses detachable sessions until the Windows tier-1 work.

## 7. Decisions taken

| Fork | Taken | Alternative | Cost to switch later |
|---|---|---|---|
| F1: which sessions survive | (a) opt-in: `view --detachable`, `[engine] detachable = false` (derived), `VIEW_ENGINE_DETACHABLE` | (b) every session runs on `--listen` and survives a lost terminal | Low. The spawn shape is one branch in process.rs; flipping the derived default to `true` is a one-line change after T11 shows the socket transport costs nothing felt. |
| F2: how a session is addressed | (b) named sessions, name derived from the cwd, `-2` on collision | (a) raw socket paths only | Low. Paths are accepted too (a value with `/`), so (a) is a subset that already works. |
| F3: remote reach | (a) `ssh -L` forward to the far socket | (b) a far-side relay (`socat`) over ssh stdio | Medium. Only `EngineAddr::Forwarded`'s connect changes; (b) needs `socat` on every far host. |

```console
# F1 (a) taken                              # F1 (b) alternative
$ view --detachable notes.md                $ view notes.md          # always survives
[engine] detachable = true                  [engine] detachable = false   # opt out

# F2 (b) taken                              # F2 (a) alternative
$ view --connect notes                      $ view --connect /run/user/1000/view/sessions/notes.sock
$ view --list                               $ ls /run/user/1000/view/sessions

# F3 (a) taken                              # F3 (b) alternative
ssh -N -L <local.sock>:<far.sock> devbox    ssh devbox socat - UNIX-CONNECT:<far.sock>
```

If T1 item 5 fails (the `--listen` server is not bound before `--cmd`, or `vim.wait` does not service socket RPC), F1 keeps its decision and the spawn changes to `--embed` under a view-owned relay process that holds stdio and listens. T6 stops and reports that before building.
