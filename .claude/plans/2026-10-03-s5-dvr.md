## 1. Design

### 1.1 Who owns what

```
view-core   native/dvr.rs     Dvr: recording flag, input log arena, frame-seq cursor,
                              scrub cursor, markers, dead ranges, request mailbox.
                              No ratatui, no I/O, no hashing, no rmpv.
            update/dvr.rs     :View dvr verbs, scrub keys, branch refusals, branch prompt.
view-tui    dvr.rs            FrameRing (public, ratatui-free API), CellView, ScrubMove.
            paint/record.rs   capture from Shadow (front vs back over painted rows);
                              load a reconstructed frame back into Shadow.
            terminal.rs       Term::record_frame, Term::draw_recorded.
view        dvr.rs            DvrLoop: owns FrameRing + dvr-io writer; reads the mailbox.
            dvr/io.rs         dvr-io BackgroundWriter thread: hashing, export, clip read.
            dvr/clip.rs       .vdvr encode/decode (the format below).
            dvr/branch.rs     replace(): wait_exit + recovery::replace_engine + replay.
view-native config/dvr.rs     DvrTable, DvrConfig, resolve/report.
```

### 1.4 Usage

```toml
[dvr]
enabled = false   # true: record this session's painted frames and input for rewind
max_mb = 64       # memory the recording may hold; oldest whole frames are dropped past it
```

Derived, with no knob: the input-log arena is `max_mb/8` and is reserved at start. A keyframe group closes after w·h delta cells or 256 frames. The seconds step is 1 s. The export directory is the cwd. Env overrides follow the derived names `VIEW_DVR_ENABLED` and `VIEW_DVR_MAX_MB`.

| Input | What it shows |
|---|---|
| `<leader>fr` / `:View dvr scrub` | Freezes the screen on the newest recorded frame. The bottom row becomes the scrub bar: `DVR  -12.4s  frame 812 (oldest 3)  h/l frame  H/L 1s  g/G ends  b branch  e export  q close`. |
| `h` / `l` | One frame back or forward. |
| `H` / `L` | One second back or forward. |
| `g` / `G` | Oldest / newest retained frame. |
| `b` / `:View dvr branch` | Leaves scrub and opens the branch prompt: "Branch from frame 812? This replaces the editor. Unsaved: a.rs, b.rs. Changed on disk: c.toml. [y] branch  [n] cancel". It refuses outright under stdin relay, in a clip, on a dead frame, or past the input-log end. |
| `e` / `:View dvr export [PATH]` | Writes `view-dvr-<unix secs>.vdvr`, or PATH. Toast: "DVR clip written: PATH". |
| `:View dvr play PATH` | Opens a clip in scrub with branch and export off. The bar reads `CLIP name.vdvr …`. `q` returns to the live session. |
| `q` / `<Esc>` / `:View dvr close` | Back to the live screen, fully repainted. |
| `dvr.enabled = false` | `<leader>fr` is not registered. `:View dvr …` raises "DVR is off: set [dvr] enabled = true". |

## 2. Performance bound (owed in commit bodies)

- **Per recorded input** (`Dvr::record`): one `Vec<u8>::extend_from_slice` of the notation, paste text or mouse strings into an arena reserved at `enable`, plus one `Entry {kind, after_frame, start, len}` push into a reserved Vec. No allocation in steady state. The copy is the input's own bytes. When the arena is full, recording of inputs stops and `overflowed_at` is set. It never reallocates.
- **Per painted frame** (`Term::record_frame`): runs only when `draw_surface` returned true, after the stdout write, so it sits outside `output_path`'s interval. The work is O(changed cells): for each painted row run, compare `front[i]` to `back[i]` and clone the changed `Cell` into the open group's reserved Vec, with capacity w·h. A ratatui `Cell` clone allocates only when a grapheme exceeds 24 bytes, because CompactString is inline up to 24. A keyframe copies w·h cells into a Vec recycled from the pool (`Arc::try_unwrap` on eviction). No allocation in steady state except the first lap of the ring and graphemes over 24 bytes.
- **Scrub paint**: O(group cells) to reconstruct, which happens only while scrubbing. The live path is untouched.
- **Memory ceiling** (commit body only, never in doc comments): a group is at most about 2·w·h cells. A full-screen scroll makes every frame a keyframe, so the ring holds about `max_mb / (w·h·sizeof(Cell))` frames. That is seconds of a fast scroll and long stretches of typing. A `// ponytail:` comment on `FrameRing` names row dedup or compression as the upgrade path.
- **Disabled**: `DvrLoop::start` returns `None`. The loop pays one `Option` check per pass and `update` pays one bool load (`is_recording`).

**Format `.vdvr` v1.** All integers are little-endian.

```
offset size  field
0      8     magic  b"VIEWDVR\0"
8      2     version u16 = 1          (decoder refuses > 1)
10     2     flags   u16: bit0 inputs present, others 0
12     4     reserved u32 = 0
then records until End:
  1  tag u8
  4  len u32   = payload byte count (a decoder skips unknown tags by len)
  len payload
tags:
 0x01 Keyframe  seq u64, at_us u64, w u16, h u16, cur_x u16, cur_y u16, cur_on u8, then w*h Cell row-major
 0x02 Delta     seq u64, at_us u64, cur_x u16, cur_y u16, cur_on u8, n u32, n × (x u16, y u16, Cell)
 0x03 Input     after_frame u64, kind u8 (0 Key, 1 Paste, 2 Mouse, 3 Resized), body:
                  Key/Paste: utf-8 bytes to end of payload
                  Mouse: row u16, col u16, then 3 × (len u8, utf-8) for button, action, modifier
                  Resized: width u16, height u16
 0x04 Marker    frame u64, kind u8 (0 EngineRestart, 1 Branch, 2 Invoke)
 0x05 Dead      first u64, last u64
 0xFF End       frames u64, inputs u64  (len = 16; must be last)
Cell: sym_len u8, sym utf-8 (sym_len bytes), fg u32, bg u32, ul u32, modifier u16
color u32: byte3 tag 0 Reset | 1 named (byte0 = 0..15) | 2 indexed (byte0) | 3 rgb (byte2=r, byte1=g, byte0=b)
```

Record order: every Keyframe/Delta in seq order, then Inputs in log order, then Markers, then Dead ranges, then End. A file without End is truncated, and the decoder refuses it.

## 6. Known limits (stated in T6's commit and the spec decision entry)

- Replay reproduces input, not time. Effects driven by timers, LSP or async replies, and `timeoutlen` chord ambiguity can diverge.
- Files the user saved since recording began show as "changed on disk", which is correct because the replacement reads today's disk. The prompt offers the override.
- Frames painted while scrubbing are not recorded. The engine keeps running and the live screen repaints in full on close.
- A clip holds frames and input. It is watchable, and it is not branchable in another session.

## 7. Open forks

**F1. Playback in-session (recommended) vs standalone.**

```
:View dvr play clip.vdvr      # recommended: same painter, same keys, q returns to work
view --play clip.vdvr         # alternative: no engine spawned; needs a second loop in main.rs (873/1000)
```

In-session reuses `draw_recorded` and the scrub keys without changing main.rs. Add `--play` later if clips are shared with people who don't run view.

**F2. Remote disk check: unverifiable prompt (recommended) vs hashing through the engine.**

```
Branch from frame 812? … Disk not checked on the remote host. [y] branch [n] cancel   # recommended
Branch from frame 812? … Changed on disk: c.toml                                      # via RPC luaeval sha256 per file
```

The engine route puts file reads on the RPC path and needs a new RpcCall. The prompt keeps "all file I/O in view" honest.

**F3. Bound by memory `max_mb` (recommended) vs time span.**

```toml
[dvr]
max_mb = 64        # recommended: a hard memory ceiling, predictable on any screen size
# span_s = 300     # alternative: friendlier to read, unbounded memory under a full-screen scroll
```

Memory is the resource that can hurt, and the scrub bar already shows how far back the ring reaches (`-12.4s`).
